# Correções da auditoria — 2026-10-27

## Objetivo e critérios

Corrigir os fluxos existentes de presença, gravação, fotos, sessão, calendário e relatório, mantendo Angular/Flask, estrutura de componentes/serviços e a apresentação atual. Commits locais pequenos, autor humano configurado, sem push/deploy ou novas dependências.

- [x] Presença permite remover, adicionar e reabrir sem perder mudanças.
- [x] Cache adota apenas gravações confirmadas; edição não altera o registro antes de salvar.
- [x] Gravações antigas recebem conflito em vez de sobrescrever outro cliente.
- [x] Upload/exclusão respeitam grupo; falhas são exibidas; publicação pode ser retomada.
- [x] Relatórios, navegação, sessão e assinaturas corrigidos.

## Mudanças de comportamento necessárias

1. PUT de grupo exige `updatedAt`; 409 pede recarregar. A mutação condiciona ID e versão no armazenamento, além da verificação prévia.
2. Participantes com presença não podem ser excluídos. IDs antigos sem cadastro aparecem como “Participante removido” no relatório e não entram no sorteio.
3. Fotos aceitam JPEG/PNG/GIF/WebP até 4 MiB. O input mantém tentativas pendentes; arquivos concluídos não são reenviados na mesma seleção. Publicação pendente com ID conhecido é retomada sem novo asset enquanto o upload permanece selecionado. Reabrir o editor não republica rascunhos.
4. URLs do editor carregam o ID por query string, permitindo reload. Callbacks do Hub são removidos ao destruir a tela/diálogo.
5. O backend lê os dados do grupo em DRAFT para recuperar gravações parciais. Fotos são listadas apenas em PUBLISHED; a exclusão mantém a operação original de despublicar, sem republicação automática.

## Limites e implantação

- Publicar FE e BE de forma coordenada: frontends antigos não enviam revisão e terão gravações recusadas. Não houve push/deploy.
- Homologar login, dois clientes concorrentes e upload real com token de grupo. O token precisa de leitura DRAFT, atualização condicional e despublicação/publicação de foto. Não foram alteradas permissões ou dados de produção.
- Falha ambígua do Hygraph após criar um asset pode deixar armazenamento sem vínculo. Assets não são apagados automaticamente: uma resposta perdida não prova que o arquivo esteja sem uso. Esse subcaso do achado 09 permanece como limitação operacional; recuperação de publicação com ID conhecido foi implementada e testada.
- A validação de imagem verifica assinatura/tamanho, sem adicionar decodificador ou conversor. Formatos HEIC e outros não são aceitos.
- Os testes adicionados, os scripts de diagnóstico e seu comando de execução foram removidos por solicitação do usuário. Os resultados acima registram verificações realizadas antes dessa remoção; as correções de aplicação foram preservadas.
